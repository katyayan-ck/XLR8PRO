## 1. Grounding Rules

- Never write standalone logic for users, employees, contacts, people, org filters, vehicle masters, keyword values, pricing, accessories, auth OTP, notifications, or documents. Use the helper wrappers in §7.
- You have complete read access to this workspace. Examine file definitions before generating code so contracts stay consistent.
- Do not query raw Eloquent models from controllers when a service already owns the operation.
- Do not invent regex for phone / PAN / Aadhaar / address sanitisation. `PersonService` already does this.
- Do not hit org/vehicle master tables directly from new code when `OrgService` / `VehicleService` / `KeywordValueService` already cache them.
- Do not hardcode Excel header labels in importer logic. Use `field_code` via `SheetHeaderService` plus `SynonymService`.
- Do not calculate or publish on-road pricing for incomplete vehicles.
- Do not create fresh Price List stubs as `INACTIVE`. Fresh stubs are `INCOMPLETE`.
- Do not load an entire pricing workbook into memory. One sheet, cap columns (~AZ), chunk rows, disconnect + GC.
- Do not seed zero-value addon/rule rows under ANY on export (they would override ANY on re-import).

## 4. Domain invariants that must never be broken

### 4.1 Vehicle master (project-life constant)

Hierarchy: **Segment → SubSegment → Model → Variant (one row per colour)**.

- `vehicle_model.code` = stem **WITHOUT** colour (last 2 chars of Model Code stripped). On Price List create, model code is OEM Model uppercased.
- `vehicle_variant.code` = **FULL** OEM / Model Code **WITH** colour.
- `color_code` = last 2 chars of Model Code. Used for `color`, `color_code`, and default colour name.
- Every child stores ancestor codes: `segment_code`, `sub_segment_code`, `model_code`.
- Colour is **not** a standalone required entity for pricing identity. It lives on the variant row.
- Detect vehicles from **Price List sheets only**. PV Vehicle / CV Vehicle sheets are retired.

New vehicle from Price List detect:

1. Lookup Variant by full Model Code. If found, reuse ancestors. Do not rewrite specs.
2. If missing: Segment = first token after `"Price List"` in sheet title (`Price List PV` → PV, TZU → LMM, TAXI → PV). Create Segment + SubSegment (same code/name temporarily OK). Create Model (`code` = stem / OEM Model, `name`/`oem_name` from OEM Model). Create Variant with full code, ancestor codes, colour from last 2 chars.
3. Do **not** invent display_name / fuel / permit / drivetrain.
4. Status = **INCOMPLETE**. Never INACTIVE on create.

### 4.2 Vehicle status (four values, not a boolean)

| Status         | Meaning                                                       |
| -------------- | ------------------------------------------------------------- |
| `INCOMPLETE`   | Missing required fields. Fresh Detect stubs. Cannot be sold.  |
| `ACTIVE`       | Complete **and** for sale. `is_active` is true **only** here. |
| `INACTIVE`     | Operator took it off sale. May still be complete.             |
| `DISCONTINUED` | No longer manufactured.                                       |

Active requires completeness. Complete may still be Inactive or Discontinued.

### 4.3 Completeness gate (Vehicle Info import only — not Price List detect)

**Always required:** Segment, Sub Segment, Fuel, Seating, Wheels, Transmission, Drivetrain, Body Make, Body Type, GST%, Permit, Taxi Price, Custom Model, Custom Variant, Display Name, Colour Name.

**Conditional (insurance-aligned):**

- Private + ICE **or** Passenger 4W + ICE → CC
- Private + EV **or** Passenger 4W + EV → Motor
- Goods → GVW
- Passenger 3W → none of CC / Motor / GVW

SSOT implementations: `VehicleService::missingFields()` / `isComplete()` and `VehicleMasterService` (narrower COMPLETE_FIELDS — prefer `VehicleService` for the full gate).

### 4.4 Global Excel match rule (project-wide)

- Header **Model** or **Variant** → match `vehicle_model.name` and `vehicle_variant.display_name`.
- Header **OEM Model** and/or **OEM Variant** → match `vehicle_model.name`/`oem_name` and `vehicle_variant.oem_name`.
- Header **Model Code** / **OEM Code** / **M Code** / **Vehicle Code** → `vehicle_variant.code` (full code WITH colour). Never append colour again.

### 4.5 Rule / scope matching (project-wide)

- `ANY` / blank / `ALL` / `*` = all descendants at that level.
- Comma-separated = union.
- More specific row **replaces the entire previous match** (not field-merge).
- Trim + case-insensitive.
- Resolve typos through `SynonymService` **before** matching (`Branch`, `Fuel`, `Segment`, `Permit`, etc.).

### 4.6 Pricing pipeline invariants

- One active `ImportSession` at a time. Discard or complete before starting another.
- Stages are gated. Incomplete vehicles are listed in impact summary and **skipped** by calculate.
- Same-WEF re-import updates the live row. Different WEF expires previous (`is_active=0`, `expired_on=WEF`) then inserts.
- Group import expires **only that group** (RSA does not expire Shield). No TRUNCATE of live history.
- Do not calculate until addons written > 0 AND (rules kept OR rules written > 0).
- Pricing JSON contract uses **fixed keys**. Unused keys present with 0/null. Consumers ignore zeros. See `PricingJsonContract`.
- RTO “Tax Factor” text (`% of Rounded Up ESR`) is **not** a decimal. Store formula in `tax_basis` (varchar). Numeric rate in `tax_slab`.
- Permission: `manage_pricing`.
- Process log: `storage/logs/pricing/pricing_process_session_{sessionId}.log` when `PRICING_PROCESS_LOG` is on.

### 4.7 Accessory catalog invariants

- Types: `Accessory`, `Ceramic`, `PPF`, `Maxicare`, `GPS_VLTD`, `RTO_Tape`, `Kazam`.
- Import is **purge + reload** of catalog tables.
- Scope dimensions: segment / model / variant / permit. NULL = ANY.
- Fetch contract: all four keys required. Either **all ANY** or **all concrete**. Mixed combinations are rejected.
- Bundle list (`type=all`) excludes `RTO_Tape` and `Kazam` unless fetched explicitly.
- Import captures MRP (Rounded) and Discount column only. Missing → 0. Do not fall back to NDP / Retn %.

## 5. Pricing workflow (what exists)

Staged multi-workbook pipeline. Operator with `manage_pricing`:

1. Start / resume / discard session (one active).
2. Detect vehicles from selected **Price List** sheets + WEF.
3. Export / import **Vehicle Info** to complete stubs.
4. Import price lists (chunked, complete vehicles only).
5. Import Addons & Discounts (Dealer Charges, Shield, RSA, Exchange, Corporate).
6. Import / keep Insurance + RTO + CSD rules.
7. Calculate & Publish snapshots (Hold can block quote/booking).

Jobs:

- `App\Jobs\Vehicle\Pricing\DetectPricingWorkbookJob`
- `App\Jobs\Vehicle\Pricing\ImportPriceListsJob`

## 6. Approval Engine (locked behaviour — no impl yet)

Standalone future `ApprovalPowerService` (not started).

Locked ideas you must not contradict if asked to design later:

- Topic tree: Main → Sub → Item.
- Org + vehicle scope matching **reuses** `OrgScopeService` patterns.
- Dynamic power types: amount / % / flag.
- Four modes: Static / Linear / Open-to-all / Variable.
- Open-to-all = parallel visibility + highest-level-wins + requester-owned closure.
- Variable is an inheritance marker only.
- Rule snapshot at request creation.
- Authority ≠ Visibility ≠ Decision.
- Topic-then-scope matching (no single specificity score as a business rule).
- Immutable events + projection.
- Ask revisions; same-level latest-wins.
- Soft minimum = warning.
- Composite Discount Request (Addendum A): one Header owns many Parameter Lines; each Line is an isolated state machine; Header Accept/Reject closes everything; `request_type` = `numeric_change` | `removal`.
- Department / Division are **not** matching dimensions in v1.
- Soft-archive after configurable inactivity days.

Do not implement schema or PHP until explicitly requested.

## 8. Matching cheatsheet (copy these algorithms, don't rewrite them)

### 8.1 Synonym then match

```
raw = trim(cell)
canonical = SynonymService::resolve(entityType, raw)
codes = OrgScopeService::expandCodes(type, canonical, parentContext)
```

### 8.2 Header resolution

```
[$headerIdx, $fieldMap] = SheetHeaderService::findHeaderRow($sheetCode, $matrix, $maxScan)
$value = SheetHeaderService::val($row, $fieldMap, 'model_code')
```

Hard aliases exist for `m code`, `material code`, `ex showroom pre subsidy`, etc. Add new labels to the **sheet_headers registry**, not to importer ifs.

### 8.3 Price List memory rules

- `setLoadSheetsOnly([$title])`
- Cap columns at `AZ`
- Chunk 50 rows
- `disconnectWorksheets()` + `gc_collect_cycles()`
- Skip row if profile is not `is_vehicle_master_complete`
- Skip row if no ex-showroom (and cannot derive from MM invoice / assessable+GST)

### 8.4 Accessory fetch

AccessoryService::list([

## 10. What not to do

- Do not create a second Person / Org / Vehicle / Accessory / Pricing engine.
- Do not use `INACTIVE` as the default for newly detected vehicles.
- Do not allow `is_active=true` on incomplete variants.
- Do not treat colour as a fifth required master table for identity.
- Do not match display-name columns against OEM names or vice versa.
- Do not whole-workbook `toArray()` on CSD / fat price lists.
- Do not implement Approval Engine v1 schema “while you’re here”.
- Do not drop audit columns or soft-delete columns on new tables.
- Do not put secrets, OTP values, or FCM tokens in logs in production paths.
- Do not change Pricing JSON keys without a versioned contract change signed off by the user.
- Do not generate migrations when the user asked for SQL, or SQL-only dumps when they asked for migrations.
