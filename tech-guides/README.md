# Tech guides — the load map

Every developer and AI-agent guide for Xceler8 (XLRM, Track A) lives here (DEC-086). **Load only what the task needs:**
start from the row for your task, read the card first, and open a detail file only when the card is not enough. Never
paste whole folders into a prompt.

| Folder | What is in it | Size |
|---|---|---|
| [`00-project.md`](00-project.md) | The one-page project card: what the app is, stack, modules, where everything lives | tiny — read first in a new session |
| [`architecture/`](architecture/README.md) | Layers, `BaseModel`, entity services, `Result`, model → table → writer map, data dictionary, decisions summary | medium |
| [`modules/`](modules/README.md) | One guide per business module (IAM, Org, Person, HR, Vehicle, Pricing, CRM, Booking, Accounts, Spares, Dashboard, v1 API adapters); the README has a short card per module | large — one file per task |
| [`platform/`](platform/README.md) | Shared utilities (Settings, Notify, Chat, Docs, Tasks, Tickets, Approvals, Templates, Email / SMS / WhatsApp / Telephony), UI kit, cookbook, testing, reference of codes / events / settings | large — one file per utility |
| [`api/`](api/index.md) | Mobile API v1: module index, per-module docs (every param, rule and response), Postman collections, common errors | medium |
| [`frs-and-workflows/`](frs-and-workflows/README.md) | Every FRS / locked spec, the approved design plans (status kept current), and short workflow cards (pricing process, sales lifecycle, approvals, the change workflow) | FRS large — read the section you need |

## Task → what to read

| Task | Read (in order) |
|---|---|
| New session / new agent | `00-project.md` → `.ai/state/handoff.md` → `docs/todo.md` (only the rows you work on) |
| Change a model / service in module X | the module card in `modules/README.md` → `modules/X.md` → `.ai/rules/modules/*` for that area (auto-loaded by path) |
| Write or import entity data | `architecture/core.md` (Entity services) → the module guide's "writers" |
| Vehicle pricing | `frs-and-workflows/workflows/pricing-process.md` → `modules/pricing.md` → spec `frs/pricing-machine-spec-v3.1.md` (the section) |
| Enquiry → quotation → booking | `frs-and-workflows/workflows/sales-lifecycle.md` → `modules/crm-enquiry-quotation.md` / `modules/sales-booking.md` → `frs/sales-combined-frs.md` |
| Approvals / discount gates | `frs-and-workflows/workflows/approvals.md` → `platform/07-approvals.md`, `08-…` |
| Use a platform utility | `platform/README.md` (rules for all) → the utility's guide → `platform/16-reference.md` for codes |
| Screens / UI | `.ai/rules/ui.md` (auto) → `platform/ui-kit.md` |
| Mobile API | `api/index.md` → `api/{module}.md` |
| Permissions / scoping / login | `modules/iam-auth.md` → skill `xcelr8-rbac-debug` when debugging |
| Database tables | `.ai/knowledge/db/{prefix}.md` (generated cards) or the Boost `database-schema` tool |
| A bug | `.ai/state/bugs-index.md` → grep `### BUG-NNN` in `docs/bugs/open.md` / `closed.md` |
| Why something is the way it is | `architecture/decisions-summary.md` → grep `DEC-NNN` in `docs/decisions/decision-log.md` |
| What changed on a date | grep `## YYYY-MM-DD` in `docs/changelog.md` (never load it whole) |

## Where the rest lives (not guides)

| Path | Role |
|---|---|
| `CLAUDE.md` / `AGENTS.md` | Always loaded; generated by `php artisan boost:update` from `.ai/guidelines/` — keep short and stable |
| `.ai/rules/` → `.claude/rules/` | Short rules, auto-loaded when a matching path is touched (`paths:` frontmatter) |
| `.ai/skills/` → `.claude/skills/`, `.agents/skills/` | On-demand skills (loaded by description) |
| `.ai/knowledge/db/` | Generated DB schema cards (`php artisan ai:refresh-context`) |
| `.ai/state/handoff.md`, `bugs-index.md` | Live hand-over; generated open-bug index |
| `docs/` | Project records: `todo.md`, `changelog.md`, `bugs/open.md`, `bugs/closed.md`, `decisions/decision-log.md`, and the date-wise `daily/DD-MM-YYYY/{handoff,changelog,accomplishments}.md` |
| `_backup/` | Superseded files, git-ignored, never read by agents (history only) |

## Keeping guides true
A change to a model, service, business rule, screen standard or API updates its guide **in the same commit**
(`.ai/rules/app.md`). New guide → add it to its folder README and, if it serves a task, to the table above.
